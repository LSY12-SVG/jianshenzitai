# 健身姿态识别算法

一个基于 `MediaPipe Tasks Vision` 的浏览器端姿态分析项目，当前聚焦于 4 类规则动作的单动作分析：

- 深蹲
- 俯卧撑
- 平板支撑
- 哑铃弯举

项目支持两种视频输入方式：

- 本机摄像头直接分析
- 手机前摄通过 WebRTC 远端接入电脑端分析

当前版本的核心目标不是复杂分类模型，而是围绕 `关键点 -> 时序特征 -> 动作分析器 -> 标准事件 -> 时间轴展示` 这条链路，验证规则计数和动作反馈是否可用。

## 当前状态

当前项目已经不是“同时检测四种动作并自动切换”的方案，而是：

- 用户先选择一个动作
- 系统只针对该动作做特征分析和计数
- 页面重点展示 `动作次数/组数` 和 `时间频率轴`

这套结构的优点是：

- 更容易针对单个动作单独调规则
- 不会被跨动作误判干扰计数
- 离线视频评测和实时页面复用同一套分析器逻辑

## 功能概览

### 1. 实时姿态识别

- 调用 MediaPipe Pose Landmarker 输出 33 个关键点
- 在视频画面上叠加关键点和骨架连线
- 显示渲染 FPS、单帧推理耗时、检测人数、关键点数量、分辨率、推理设备
- 支持 `Lite / Full / Heavy` 三种模型切换
- 支持镜像显示和关键点编号显示

### 2. 动作分析

- 深蹲：计次数
- 俯卧撑：计次数
- 平板支撑：计保持组数和保持时长
- 哑铃弯举：计次数

页面会同步展示：

- 当前分析动作
- 当前分析状态
- 动作次数 / 组数
- 当前频率 / 保持时长
- 当前阶段
- 时间轴摘要
- 4 个关键调试指标

### 3. 时序特征展示

页面会实时输出当前帧序列的时序特征，便于调规则：

- 关键点序列
- 关节角度序列
- 关键点速度
- 重心变化
- 腕部轨迹
- 身体朝向
- 动作方向
- 器械辅助信息占位

### 4. 手机远端接入

支持用手机前摄替代电脑摄像头：

- 电脑端创建远端会话
- 页面生成二维码和会话码
- 手机扫码打开 `mobile.html`
- 手机通过 WebRTC 把视频流推回电脑端
- 电脑端继续用同一套 MediaPipe 和动作分析器处理

## 项目架构

当前代码已经按“特征层 / 动作层 / 事件层 / 校准层 / 展示层”拆分。

### 特征层

入口仍在 `src/main.js`。

`computeTemporalFeatures(...)` 会从关键点中统一提取：

- 膝、髋、肘、肩角度
- 重心、髋、肩、腕部位移和速度
- 角度范围
- 趋势斜率
- 身体朝向
- 侧身主肢体
- 稳定性指标

### 动作层

`src/engine/analyzers.js` 中为每个动作维护独立分析器，统一输出：

- 当前阶段
- 是否完成一次 rep / 一段 hold
- 当前频率
- 关键调试指标
- 标准事件

### 事件层

`src/engine/events.js` 将内部状态统一转成标准事件：

- `rep`
- `hold_start`
- `hold_end`

时间轴和评测报告都直接消费这些事件，不直接读取分析器内部变量。

### 校准层

`src/engine/calibration.js` 会在动作开始前做短暂基线校准，用于按用户站位和身体比例调整部分阈值。

### 时间轴层

`src/engine/timeline.js` 负责把事件流转成页面上的“时间频率轴”展示数据。

### 远端采集与信令

- 电脑分析页入口：`index.html`
- 手机采集页入口：`mobile.html`
- 手机端逻辑：`src/mobile.js`
- WebRTC 与信令模块：`src/rtc`
- 信令与 HTTPS 服务：`server/index.js`

## 运行环境

- Node.js 18+
- Chrome / Edge 等现代浏览器
- 手机远端接入时，手机和电脑需在同一局域网内

## 安装

```bash
npm install
```

## 启动方式

### 开发模式

```bash
npm run dev
```

这会同时启动两部分：

- Vite 前端开发服务：`http://127.0.0.1:5173`
- 信令服务：`http://127.0.0.1:8787`
- HTTPS 信令服务：`https://127.0.0.1:8788`

其中：

- `5173` 用于电脑端页面开发和本机摄像头分析
- `8787 / 8788` 用于远端手机会话创建、二维码接入和 WebSocket 信令

### 只启动前端

```bash
npm run dev:client
```

适合只调页面或本机摄像头分析。

### 只启动信令服务

```bash
npm run dev:signal
```

适合单独调试远端接入链路。

### 构建

```bash
npm run build
```

会同时构建两个入口：

- `index.html`
- `mobile.html`

### 构建后预览前端

```bash
npm run preview
```

注意：`preview` 只用于静态前端预览，不包含信令服务，不适合完整验证手机远端接入。

### 构建后启动完整服务

```bash
npm run build
npm run serve
```

`serve` 会启动 `server/index.js`，如果 `dist/` 存在，则会同时托管构建后的分析页和手机页。

## 页面使用说明

### 本机摄像头模式

1. 打开电脑端页面
2. 选择动作
3. 保持默认“本机前置摄像头”
4. 点击“启动摄像头”
5. 观察关键点绘制、计数、频率和时间轴

### 手机前摄远端模式

1. 启动 `npm run dev` 或 `npm run serve`
2. 在电脑端页面将“视频源”切换为“手机前摄远端接入”
3. 创建手机会话
4. 用手机扫码打开采集页
5. 手机浏览器接受 HTTPS 自签名证书和摄像头权限
6. 在手机上点击“启动前摄推流”
7. 回到电脑端查看远端视频分析结果

### 远端模式注意事项

- 手机浏览器通常要求 `HTTPS` 安全上下文，否则会拒绝摄像头
- 当前服务端会自动生成自签名证书
- 手机首次访问时通常需要手动接受证书风险提示
- 手机与电脑需要在同一局域网下

## 动作规则说明

当前版本全部为规则法，不包含训练好的分类模型。

### 深蹲

核心判断：

- 髋部高度周期性下降和上升
- 膝角周期性变小再变大
- 肩部相对稳定

推荐视角：

- 正面
- 略微侧身

### 俯卧撑

核心判断：

- 身体接近水平
- 肘角形成明显峰谷变化
- 肩部和重心存在上下相位变化

推荐视角：

- 侧身

### 平板支撑

核心判断：

- 肩、髋、踝接近共线
- 身体整体波动较小
- 支撑点稳定

推荐视角：

- 侧身

### 哑铃弯举

核心判断：

- 上臂相对稳定
- 肘角周期性收缩与伸展
- 腕部存在上下轨迹

推荐视角：

- 侧身

## 离线视频评测

项目包含离线视频评测脚本：

- 脚本：`scripts/evaluate-videos.mjs`
- 报告输出：
  - `reports/video-evaluation-report.md`
  - `reports/video-evaluation-report.json`

评测特点：

- 复用页面同一套分析器和事件层
- 以固定 FPS 对本地视频采样重放
- 输出关键点覆盖率、首次事件响应、计数结果和时间轴

当前脚本中的 `videoItems` 默认还没有完整填入每个视频的 `expectedCount` 真值次数，因此：

- 可以看系统输出次数
- 可以看首次响应时间
- 可以看关键点覆盖率
- 但误检 / 漏检统计仍需要先补真值标注

## 已知限制

### 1. 当前仍是规则法

系统没有训练分类模型，也没有端到端时序网络，因此对以下情况仍较敏感：

- 视角偏差
- 遮挡
- 光照变化
- 动作幅度过小
- 节奏过快或过慢

### 2. 俯卧撑计数仍在持续调优

目前深蹲和弯举相对更稳定，俯卧撑已经从早期明显欠计数逐步优化，但在真实视频上仍可能出现少量漏计，尤其在：

- 顶点伸展不充分
- 节奏很快
- 动作后段疲劳导致幅度下降

### 3. 手机远端模式依赖浏览器环境

远端采集的稳定性会受到以下因素影响：

- 手机浏览器对摄像头和 WebRTC 的兼容性
- 自签名证书是否被接受
- 局域网延迟和抖动

### 4. 离线自动评测对浏览器运行环境有依赖

评测脚本依赖浏览器自动化和 MediaPipe WASM，在不同机器上可能遇到：

- 视频编解码差异
- 无头浏览器兼容性差异
- 长时间批量回放时的 WASM 中断

## 后续建议

如果继续迭代，优先级建议如下：

1. 给离线评测补齐每个视频的真值次数
2. 继续收敛俯卧撑计数器，尤其是顶点闭环和快节奏漏计
3. 给每个动作增加更清晰的阈值配置面板
4. 继续扩展器械辅助信息和更稳定的时序特征
5. 在规则法稳定后，再考虑引入动作分类模型或时序模型
